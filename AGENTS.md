# AGENTS.md

Правила для агентов и разработчиков, работающих с этим репозиторием (minipoll).

## Проект

- Приложение: «Мини-анкета» — тестовый full-stack стенд для ДЗ №1
- Backend: NestJS + TypeScript
  - `GET /questions` — список из 3–5 жёстко заданных вопросов
  - `POST /answers` — приём ответов, хранение в памяти (без БД)
- Frontend: React — загрузка вопросов, форма, отправка ответов, экран «Спасибо!»
- Менеджер пакетов: npm
- Платформа: Windows, команды должны работать в cmd
- Приложение тестовое: минимальность важнее масштабируемости — не добавлять БД, авторизацию и прочую «боевую» инфраструктуру без явной просьбы

## Команды

- Установка зависимостей: `npm install`
- Сборка: `npm run build`
- Тесты: `npm test`
- Линтер: `npm run lint`
- Типы: `npm run typecheck`

После завершения задачи обязательно запускать `lint` и `typecheck`, если они настроены.

## Стиль кода

- Язык: TypeScript (strict mode), без `any` без явной необходимости
- Комментарии — только когда они действительно нужны; не писать поясняющие комментарии к очевидному коду
- Именование: `camelCase` для переменных/функций, `PascalCase` для типов/классов/компонентов, `SCREAMING_SNAKE_CASE` для констант
- Один файл — одна ответственность; избегать файлов больше ~300 строк без веской причины
- Следовать существующим соглашениям в кодовой базе, а не вводить новые
- Не добавлять зависимости без необходимости; сначала проверять, что уже используется в проекте

## Git

- Не коммитить без явной просьбы пользователя
- Не пушить в удалённый репозиторий без явной просьбы
- Никогда не коммитить секреты, ключи, `.env`-файлы с реальными данными
- Сообщения коммитов: краткие, на английском, в императиве (например, `add poll creation endpoint`)
- Ветки: `feature/<краткое-название>`, `fix/<краткое-название>`

## Безопасность

- Никогда не логировать и не хардкодить секреты, токены, пароли
- Валидировать все входные данные из внешних источников (API, формы)
- Параметризованные запросы к БД — никаких склейких SQL-строк

## Промпты и отчёт (REPORT.md)

- Все промпты, которые пользователь использует в ходе работы, обязательно сохранять в файл `REPORT.md` в раздел «Промты»
- Сохранять промпт полным текстом, а не пересказом, сразу после его получения
- Обновлять раздел «Промты» в `REPORT.md` после каждого нового промпта пользователя
- Обновлять раздел «Промты» в `REPORT.md` можно без подтверждения пользователя
- Любые другие изменения в `REPORT.md` вносить только после явного подтверждения пользователя
- Если `REPORT.md` или раздела «Промты» ещё нет — создать его при первом промпте

## Работа агента

- Писать рассуждения (thinking) по-русски

- Перед изменениями изучить окружающий код и существующие паттерны
- Минимальные, целевые изменения — не рефакторить то, о чём не просили
- После изменений запускать тесты/линтер, если они доступны
- Не оставлять мёртвый код, закомментированные блоки и отладочный вывод (`console.log`) в финальном коде
